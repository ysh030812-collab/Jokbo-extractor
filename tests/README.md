# 회귀 테스트

전부 `web/` 웹앱을 대상으로 한다. 실제 족보(2020·2022·2023 감면 기말)에서
파서가 걸려 넘어졌던 구간을 픽스처로 옮겨 두었다. 저작물이므로 문항 내용이
아니라 **번호·구분점·선지·슬라이드 구조**만 재현한다.

## 준비

```sh
npm install                          # @xmldom/xmldom, fflate, playwright
pip install python-docx pymupdf pillow
python3 tests/make_fixtures.py       # DOCX 픽스처
python3 tests/make_e2e_inputs.py     # 브라우저 e2e 입력 (풀이 PDF·강의안)
python3 tests/make_big_solution.py   # 실제 규모(511쪽) 풀이 PDF — 색인 변환 검증용
```

## 돌리기

```sh
node tests/test_js.mjs       # 파일명(학기 유무·NFC/NFD) · 블록 범위 · JSON 파싱
node tests/test_scan.mjs     # 풀이 PDF 블록 스캔 — 2020 실물 구조 (주관식·출처 슬라이드)
node tests/test_docx.mjs     # 시험지 DOCX 파싱
node tests/test_download.mjs # 내려받기 — 아이패드는 공유 시트, 그 외는 링크
node tests/test_manual.mjs   # Claude 없이 번호만 적어 고르는 길
node tests/test_exam.mjs     # 시험지 PDF — 문제 나누기와 오려내기
node tests/test_stale.mjs   # 파서를 고친 뒤 이미 등록해 둔 파일을 다시 읽기
node tests/test_ui.mjs       # 1·2단계 접기, 과목 나눠 등록하고 갈아타기
node tests/e2e.mjs           # 브라우저 전 과정 (CHROME=<크로미움 경로> 로 지정 가능)
```

`e2e.mjs` 는 등록 → 파일 삭제 → 재등록 → 새로고침 → Project 조각 만들기 →
지시문 → 판정 붙여넣기 → 결과 PDF 까지 실제 브라우저에서 돌린다. 조각이
Claude 의 요청 한도(**32MB · 100쪽**) 안에 들어오는지 검사하고, 넘으면 실패한다.
결과물은 `tests/e2e_project_out.pdf` 로 남는다.

## 시험지 PDF

시험지가 PDF 로만 있는 해가 있다. 글자만 뽑아 다시 조판하면 표·그림·수식이 통째로
사라지므로, **텍스트는 어디서 자를지 찾는 데만 쓰고** 결과물에는 원본 쪽의 그 부분을
벡터 그대로 오려 붙인다. 한 줄 잘못 읽어도 내용이 깨지지 않고 자르는 선만 어긋난다.

- 문제 머리는 왼쪽 여백에서 시작하고, 번호가 **바로 다음 번호**이거나 위에 빈 줄이
  있는 줄이다. 선지(`1)`~`5)`)는 이어지는 번호로 세어 걸러 낸다.
- 소수점 배제(`(?!\d)`)는 **쓰지 않는다.** 시험지에는 `2) 15세 이상 음주량`,
  `18.100명의 방사선사진…` 처럼 번호 뒤에 바로 숫자가 오는 줄이 흔하다.
  실물 2022 소화기 4번과 2023 소화기 18번이 이것 때문에 통째로 사라졌다.
- 어디까지가 한 문제인지는 쪽을 아주 작게(1px=2pt) 한 번 그려 보고 **잉크가 묻은
  줄·칸**으로 정한다. 글줄만 보면 그림이 잘리거나 빈 종이가 딸려온다.
- 쪽을 넘어간 문제는 조각이 둘이 되고, 결과물에서 위아래로 이어 붙는다. 쪽 한 장을
  거의 다 쓰는 긴 문제는 단으로 세우되 빈 띠에서만 자른다.

`test_exam.mjs` 는 이 함정들을 그대로 재현한 합성 시험지를 브라우저에서 만들어
등록부터 결과 PDF 까지 검사한다.

## 파서를 고친 뒤

이미 등록한 파일은 **예전에 읽어 둔 결과 그대로** 기기에 남는다. 파서를 고쳐도
그 파일에는 반영되지 않는다. 실제로 `43-45.` 을 고치고도 사용자 화면에서는 그대로
안 잡혔는데, `PARSER_VER` 을 안 올려서 앱이 낡은 결과를 쓰면서 알려 주지도 않았다.

**파서를 고쳤으면 `PARSER_VER` 을 반드시 올린다.** 그러면 1단계에 안내가 뜨고
(그 단계는 접히지 않는다),

- 풀이 PDF·시험지 PDF 는 원본을 그대로 들고 있으므로 **여기서 다시 읽기** 한 번이면 된다
- 시험지 DOCX 는 원본이 없어(문제만 뽑아 뒀다) 같은 파일을 다시 골라 받아야 한다

`test_stale.mjs` 가 낡은 상태를 만들어 두고 안내 → 다시 읽기 → 복구까지 검사한다.

## 과목 나눠 쓰기

여러 과목을 한 기기에 등록해 두고 1단계 칩으로 갈아탄다. 고른 과목만 파일 목록 ·
Project 준비 · 번호 입력칸에 보이고, 고른 과목은 새로고침해도 남는다. 다른 과목을
보는 중에 파일을 올리면 그 파일이 안 보이지 않도록 올린 쪽으로 옮겨 간다 (전체를
보고 있었으면 그대로 둔다). `test_ui.mjs` 가 접기까지 함께 검사한다.

## Claude 없이 번호로 직접 고르기

3단계 아래 접이식 칸에서 시험마다 문제 번호를 적으면 Claude 를 거치지 않고 바로
목록이 된다. 이미 어느 문제를 뽑을지 알고 있을 때 쓴다.

| 적는 법 | 뜻 |
|---|---|
| `6, 7, 12-15` | 6번, 7번, 12\~15번 (네 문제) |
| `주37` | 주관식 37번 |
| `p442~444` | 번호를 모르는 그림 문제 — 원본 442\~444쪽 (한 문제) |

알아보지 못한 표기와 족보에 없는 번호는 따로 나눠 알려 준다.
`test_manual.mjs` 가 이 길을 등록부터 결과 PDF 까지 확인한다.

## 번호를 묶어 낸 문제

`43-45. 알코올성 간질환의 …` 처럼 한 문제에 번호가 여러 개 붙는 족보가 있다. 이런
문제는 첫 번호(43)를 id 로 삼되 **44·45 로 불러도 같은 항목이 나온다.** Claude 가
가운데 번호로 답하든, 사람이 `43-45` 라고 적든, 결과물에는 `43~45번` 한 장만
들어간다. 진짜 그 번호를 가진 문제가 따로 있으면 그쪽이 이긴다.

## Project 에 넣는 파일

시험지 DOCX 가 있는 연도는 그 원본을 그대로 올린다. 없는 연도(2020·2021)는
풀이 PDF 를 **자르기만** 해서 올린다 — 쪽마다 원본 쪽번호를 찍고, 어느 슬라이드가
한 문제인지는 Claude 가 보고 판단해 쪽 범위로 답한다 (`2020-기말-감면-p442~444`).

전에는 '문제 화면'만 골라 색인을 만들었는데, 어느 슬라이드가 문제이고 어느 것이
해설·출처인지 코드가 추측해야 했고 빗나갈 때마다 결함이 났다. 그 추측을 없앤 것이
지금 구조다. 블록 스캔은 **시험지가 있는 연도**에서 문제 번호 → 슬라이드를 찾는 데
계속 쓰이므로 `test_scan.mjs` 로 지킨다.

## 파일 이름 규칙

`{연도} {과목} [{중간|기말}] [풀이]` — 중간/기말은 **없어도 된다.**
이름 끝의 `풀이` 가 풀이 슬라이드와 시험지를 가른다. 시험지는 `.docx` 든 `.pdf` 든
된다 — PDF 는 문제 부분을 오려 쓰고, DOCX 는 글자밖에 없으므로 다시 조판한다.

| 이름 | 연도 | 과목 | 학기 | id 앞머리 |
|---|---|---|---|---|
| `2023 감면 기말 풀이.pdf` | 2023 | 감면 | 기말 | `2023-기말-감면` |
| `2023 감면 기말.pdf` | 2023 | 감면 | 기말 | `2023-기말-감면` |
| `2023 호흡기계 풀이.pdf` | 2023 | 호흡기계 | — | `2023-호흡기계` |
| `2023 감염과 면역 기말.docx` | 2023 | 감염과 면역 | 기말 | `2023-기말-감염과 면역` |

## 내려받기 테스트가 지키는 것

아이패드 사파리는 blob 에 붙은 `<a download>` 를 무시하는 일이 잦아 색인 파일이
아예 저장되지 않았다. `test_download.mjs` 는 아이패드 UA 로 띄워

- 공유 시트(Web Share)로 넘어가는지
- 만든 파일을 **한 번에 전부** 넘기는지
- `share()` 호출 시점에 사용자 제스처가 살아 있는지 (만들기와 받기를 나눈 이유)
- 아이패드가 아니면 링크 방식으로 내려받는지

를 검사한다. `share()` 앞에 `await` 를 넣으면 제스처 자격이 사라져 실패하므로,
바이트를 미리 들고 있다가 버튼 핸들러에서 동기로 넘겨야 한다.
